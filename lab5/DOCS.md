# Протокол RDTP (Reliable Data Transfer Protocol)

## Формат пакетов

Протокол определяет два типа сообщений (PDU): Пакет данных (Data Packet) и Подтверждение (ACK Packet). Данные передаются в бинарном виде без использования сложной сериализации (C-style structs), что обеспечивает минимальные накладные расходы.

| Поле     | Тип (C++) | Размер (байт) | Описание                                                                                           |   |
|----------|-----------|---------------|----------------------------------------------------------------------------------------------------|---|
| seqNum   | uint32_t  | 4             | Порядковый номер пакета (Sequence Number). Начинается с 0. Идентифицирует позицию данных в потоке. |   |
| dataSize | uint32_t  | 4             | Размер полезной нагрузки в байтах. Значение 0 используется как флаг конца передачи (EOF).          |   |
| data     | char[]    | 1024 (MSS)    | Полезная нагрузка (Payload). Содержит фрагмент передаваемого файла.                                |   |
|          |           |               |                                                                                                    |   |

Общий размер заголовка: 8 байт.
Максимальный размер пакета (MTU): 1032 байта.


## Пакет подтверждения (ACK Packet)

Используется получателем (Receiver) для уведомления отправителя об успешном приеме пакетов.

| Поле   | Тип (C++) | Размер (байт) | Описание                                                                            |   |
|--------|-----------|---------------|-------------------------------------------------------------------------------------|---|
| ackNum | uint32_t  | 4             | Номер подтверждения. В парадигме GBN указывает на номер успешно полученного пакета. |   |

## Выбранные алгоритмы

### Go-Back-N (Возврат на N)

Для обеспечения надежности выбран алгоритм Go-Back-N. Это выбор обусловлен его простотой реализации по сравнению с Selective Repeat и меньшими требованиями к буферизации на стороне получателя.

### Управление потоком

Используется механизм скользящего окна (Sliding Window) фиксированного размера.

* Base: Номер старейшего неподтвержденного пакета.

* NextSeqNum: Номер следующего пакета для отправки.

* WindowSize: 10 пакетов.

Условие возможности отправки нового пакета:
NextSeqNum < Base + WindowSize

###  Расчет тайм-аута

Используется статический тайм-аут (TIMEOUT_MS = 100 мс).
Таймер запускается для "старейшего неподтвержденного пакета". Если таймер истекает, происходит событие Retransmission. Если приходит ACK, продвигающий Base, таймер перезапускается для нового Base (если есть неподтвержденные данные).

### Имитация ненадежной среды

В класс UdpSocket встроен механизм симуляции:

* Потеря пакетов (Packet Loss): Перед вызовом sendto, генерируется случайное число. Если оно меньше порогового значения (PACKET_LOSS_RATE, ACK_LOSS_RATE), пакет молчаливо отбрасывается.
* Задержка (Latency): Искусственная пауза (std::this_thread::sleep_for) перед отправкой для имитации jitter'а сети.


## Обработка граничных случаев

1. Конец файла (EOF)
2. Потеря ACK
3. Полная потеря связи

## Используемые системные вызовы

* UDP Sockets: socket(), bind(), sendto(), recvfrom().
* Мультиплексирование/Таймеры: poll() — используется для ожидания ACK с заданным таймаутом. Это позволяет избежать блокирующего recvfrom и реализовать логику таймера перепосылки в одном потоке.
