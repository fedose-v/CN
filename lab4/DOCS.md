# Алгоритм обработки флага TC (Truncation)

## Бит TC в заголовке
В структуре заголовка DNS флаг TC занимает 22-й бит (если считать с 0 с конца) или 6-й бит во втором байте флагов.
В коде C++ (network byte order):
```c++
bool isTruncated = (header.flags & htons(0x0200));
```

## Алгоритм обработки
Процесс разрешения имени с учетом флага TC выглядит следующим образом:
* Первичный запрос (UDP):
    * Сформировать стандартный DNS-запрос.
    * Отправить запрос на сервер по протоколу UDP (порт 53).
    * Получить ответ.
* Проверка заголовка:
    * Распарсить заголовок ответа.
    * Проверить бит TC.
* Ветвление логики:
    * Если TC == 0: Ответ полный. Перейти к парсингу секций (Answers, Authorities, Additional).
    * Если TC == 1: Ответ усечен. Инициировать процедуру TCP Fallback.
* Процедура TCP Fallback (Повторный запрос):
    * Открыть потоковый сокет (SOCK_STREAM) протокола TCP.
    * Установить соединение (connect) с тем же DNS-сервером на порт 53.
    * Формирование TCP-пакета:
        * В отличие от UDP, сообщения DNS поверх TCP должны предваряться 2-байтовым полем длины (Length Prefix).
        * Формат: Length (2 bytes)
        * Поле Length (uint16_t) должно быть в сетевом порядке байт (htons).
    * Отправить пакет.
    * Чтение TCP-ответа:
        * Сначала прочитать первые 2 байта — это длина входящего сообщения (ResponseLength).
        * Выделить буфер размером ResponseLength.
        * Считать ровно ResponseLength байт данных из сокета.
    * Закрыть TCP-соединение.
    * Передать полученный буфер в парсер (TCP-ответы не имеют флага TC, так как TCP гарантирует доставку потока любой длины).
